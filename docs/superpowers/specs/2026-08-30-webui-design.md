# GridStar Agent WebUI 设计规格

## 目标

在当前项目增加 `webui` 目录，实现可嵌入工业软件最右侧的竖向 AI 面板。界面采用单页上下堆叠布局，由现有 FastAPI 服务在 `/ui/` 托管，并直接调用现有 Agent API。

## 范围

首版包含：

- 会话创建、选择、重命名、删除和清空
- SSE 流式聊天与停止显示
- 模型选择及 manual/auto 模式切换
- Skill 获取与选择
- Markdown 基础渲染和代码块显示
- `phase_plan`、`options`、`tool_params`、`workflow` 结构化内容渲染
- 工具调用、工具结果及工具审批
- 服务连接、错误和忙碌状态

不包含独立 Node 构建链、全屏桌面布局、多主题系统和 Qt WebChannel 桥接。

## 技术方案

使用原生 HTML、CSS 和 JavaScript，无 npm 或打包步骤。目录结构：

```text
webui/
├── index.html
├── style.css
└── app.js
```

FastAPI 挂载该目录，并将 `/ui` 重定向至 `/ui/`。所有 API 使用同源相对地址，工业软件加载 `http://127.0.0.1:1231/ui/` 即可。

## 布局

面板目标宽度为 360–440px，高度占满容器：

1. 顶栏：产品名、连接状态。
2. 会话栏：新建会话按钮、当前会话入口；历史会话以浮层呈现。
3. 消息区：占据剩余空间并独立滚动。
4. 工作流区：仅存在活动阶段计划时显示，固定在输入区上方。
5. 输入区：模式、模型、Skill 控件，文本输入和发送/停止按钮。

窄于 360px 时压缩间距并隐藏非必要文字，不产生横向滚动。

## 视觉规范

采用深色工业软件风格：深蓝黑背景、蓝青色主状态、绿色成功、橙色警告、红色错误。组件保持紧凑、低圆角和清晰边界，不使用大面积渐变、装饰图或悬浮卡片堆叠。

## 数据流

启动时依次请求 `/health`、`/config/models`、`/skills` 和 `/sessions`。选择或创建会话后读取 `/sessions/{session_id}`。

发送消息时调用 `/chat/stream`，逐帧解析 SSE：

- `text_chunk`：追加助手正文。
- `reasoning_chunk`：更新可折叠思考区。
- `phase_plan`：更新固定工作流区。
- `tool_call` / `tool_result`：渲染工具状态。
- `tool_approval_required`：渲染批准/拒绝操作。
- `skill_loaded`：更新 Skill 状态。
- `error`：结束忙碌态并展示错误。
- `done`：完成当前响应并刷新会话。

结构化 JSON 代码块在消息完成时解析为 `options`、`tool_params`、`workflow` 或 `phase_plan` 组件。参数确认使用已有聊天协议继续发送确认内容；工具审批调用专用审批接口。

## 状态与错误处理

前端只允许一个正在进行的聊天请求。请求期间发送按钮切换为停止按钮，使用 `AbortController` 中断当前 HTTP 流。断线、非 2xx 响应和无效 SSE 数据显示在消息区或顶部状态区，不清除用户已输入内容。

缺少模型配置时保留界面可用并明确提示用户配置后端。无 Skill、无会话或无阶段计划均使用简洁空状态。

## 测试与验收

- 在 360px、400px、440px 三种宽度下无横向滚动。
- 可从 `/ui/` 正常加载全部资源。
- 会话与模型接口请求成功，聊天 SSE 增量可见。
- manual/auto 和 Skill 值随聊天请求提交。
- 阶段计划、选项、参数确认和审批可操作。
- 断线、后端错误和中止请求后界面恢复可发送状态。
- 现有 Python 测试保持通过，并新增静态资源托管测试。
