# Token 用量统计设计

## 1. 目标与范围

在 WebUI 设置中心新增第四个 Tab「用量」，用于查看历史 token 消耗：

- 按供应商、按模型两个维度查看用量；
- 折线图看趋势、饼图看占比、柱状图看实测与估算构成；
- 时间范围在日历下拉中选定，支持预设区间与自定义起止日期；
- 粒度支持按小时、按天；
- 时间轴可缩放，缩放锚定鼠标位置，可突破当前档位下钻到小时桶；
- 可排序的明细表给出每个模型（或供应商）的绝对数值。

数据源是既有落盘记录，不新增写入路径，不改动消息持久化逻辑。

范围限定为 WebUI 与 Python 后端。Qt 客户端本次不实现。

## 2. 数据来源

### 2.1 已有记录

每条 assistant 消息在 `sessions/<id>/messages.jsonl` 中已带 `ts` 与 `usage`：

```json
{
  "role": "assistant",
  "ts": "2026-09-22T10:03:14.882",
  "usage": {
    "input": 12043, "output": 892, "total": 12935, "estimated": false,
    "cache_read": 8192, "reasoning": 256,
    "model": "openai/gpt-4o"
  }
}
```

字段由 [session.py](file:///d:/TRAE_project/GridStarAgent/agent/agent/session.py#L193-L232) 写入，`usage.model` 是完整的 `provider/model` 键，来自 [agent_loop.py](file:///d:/TRAE_project/GridStarAgent/agent/agent/agent_loop.py#L665) 的 `call_model_id`。

两个口径事实：

- `estimated=true` 表示该轮实时 usage 缺失、由本地估算兜底得出（[agent_loop.py](file:///d:/TRAE_project/GridStarAgent/agent/agent/agent_loop.py#L362-L395)）。统计中必须与实测分开，不得相加合并。
- 老会话可能整条没有 `usage` 字段，直接跳过，不做反推估算。

### 2.2 聚合方式：按需扫描 + 会话级缓存

新模块遍历 `SESSIONS_DIR/*/messages.jsonl`，为每个会话缓存已解析的用量记录，缓存键为该文件的 `(mtime, size)`。文件未变化时复用缓存，不重复解析。

不采用写入侧增量索引。理由：增量索引需要在 `append_assistant` 这条消息持久化路径上同步写全局流水，一旦回填或去重有缺陷会污染历史会话数据；而本地个人量级下，扫描加缓存的读取延迟已经足够低，风险收益不匹配。也不引入第三个持久化快照文件，避免多真相源。

## 3. 后端

### 3.1 新增模块

`agent/agent/usage_stats.py`，对外一个入口：

```python
def collect_usage(start: datetime, end: datetime, model: str = "") -> dict
```

内部职责：

1. 遍历会话目录，取得时间窗内的用量记录；
2. 按小时切桶；
3. 同时产出供应商维度、模型维度的聚合；
4. `model` 非空时，桶只统计该模型。

时间戳解析用 `ts[:19]` 取秒级后再 `datetime.fromisoformat`，兼容毫秒精度与旧记录。

### 3.2 接口

```http
GET /usage/stats?start=2026-09-15T00:00&end=2026-09-22T18:00&provider=openai&model=openai/gpt-4o
```

`start`、`end` 为本地时间（与消息 `ts` 同一时区口径），`provider`、`model` 可选，可同时给出。

响应：

```jsonc
{
  "range": {"start": "2026-09-15T00:00", "end": "2026-09-22T18:00", "resolution": "hour"},
  "totals": {"total": .., "input": .., "output": .., "measured": .., "estimated": ..,
             "cache_read": .., "cache_write": .., "reasoning": .., "turns": .., "sessions": ..},
  "buckets": [{"t": "2026-09-22T10", "input": .., "output": .., "total": ..,
               "measured": .., "estimated": .., "turns": ..}],
  "providers": [{"provider": "openai", "label": "OpenAI", "total": .., "input": .., "output": ..,
                 "measured": .., "estimated": .., "cache_read": .., "cache_write": ..,
                 "turns": .., "sessions": ..}],
  "models": [{"model": "openai/gpt-4o", "provider": "openai", "label": "gpt-4o",
              "total": .., "input": .., "output": .., "measured": .., "estimated": ..,
              "cache_read": .., "cache_write": .., "turns": .., "sessions": ..}],
  "candidates": {"providers": [ ... ], "models": [ ... ]}
}
```

设计要点：

- **桶始终按小时返回**，`buckets` 是权威数据。前端按「按天」粒度查看时自行按自然日向上卷，切换粒度不产生新请求。
- **`resolution` 是当前范围可用的最细粒度**。跨度超过 90 天时返回 `"day"`，`buckets` 的 `t` 为 `YYYY-MM-DD`，此时前端缩放不再下钻到小时（数据不存在，不下钻没有意义）。这样桶数量有上界，避免长跨度下产生上万点。
- **一次返回供应商与模型两套聚合**，前端切换「分组」维度不发请求。
- **`candidates` 是筛选器选项的来源**，结构与 `providers` / `models` 相同，但**只按时间窗过滤，不受 `provider` / `model` 参数影响**。下拉要列出「有调用记录」的模型与供应商，若跟着筛选缩水，筛完就再也切不回别的选项了。
- **供应商归属**：`usage.model` 前缀 → 会话 `meta.model_id` 前缀 → 都没有则记为 `unknown`，前端显示「未知供应商」。已从配置中删除的历史供应商按 ID 原样列出，不丢历史数据。
- **模型与供应商筛选走服务端**，因为 `buckets` 是跨模型聚合的结果，客户端无法事后拆出单个模型。按 `(start, end, model, provider)` 加服务端缓存，切回历史查询命中缓存。
- 时间窗内无记录时正常返回零值结构，不报错。

### 3.3 缓存失效

会话级缓存按 `(mtime, size)` 判定，新消息写入即失效。进程生命周期内不主动清理，会话数量级下内存占用可忽略。

### 4.3 筛选控件

五个胶囊下拉，视觉与现有 `.settings-field` 一致，复用主题变量。

**分组**：`模型用量`（默认）/ `供应商用量`。只决定饼图与明细表按哪个维度拆分，不改变统计数据本身，切换不产生请求。

分组不参与折线图与柱状图的序列拆分。折线图始终是输入/输出两条线，柱状图始终是实测/估算两层堆叠，与分组选了哪个维度无关；换句话说，这两个图不会按供应商或模型拆成多条序列。

**供应商**：`全部供应商`（默认）+ 当前时间窗内**有调用记录**的供应商。

**模型**：`全部模型`（默认）+ 当前时间窗内**有调用记录**的模型，选定供应商后只列该供应商名下的。

两个下拉的选项都来自 `candidates`，即「当前时间窗内真正产生过用量」的模型与供应商，不是配置里的全部模型。理由：从没调用过的模型没有任何记录，列出来只会让用户选到一片空白，看起来像功能坏了。

配套规则：

- 显示名优先取配置里的 `name`（模型的 `name`、供应商的 `name`），与设置页逐字一致；
- 历史里出现过、但已从配置中移除的模型仍会列出，并在名称后标注「未在配置中」，让用户明白它为什么不在设置页里；
- 记录缺少 `usage.model` 时归属为 `unknown`，显示为「未知供应商」；
- 选择模型时把供应商一并对齐到该模型所属供应商，避免「供应商= A + 模型= B/m」这类互相矛盾的条件查出空结果；
- 切换供应商后，原先选中的模型若不属于该供应商，回落到「全部模型」；
- 已选中的模型或供应商若在当前时间窗内没有记录（例如切换了日期区间），仍然保留下拉里不被静默清空，表格与图表按空状态渲染。清空会造下拉与表格各说各话，用户也看不到自己到底筛了什么。

**粒度**：`按天`（默认）/ `按小时`。控制前端向上卷的档位：

- `按小时`：直接用服务端小时桶；
- `按天`：按本地自然日把小时桶相加。

切换粒度不发请求。`resolution` 为 `"day"` 时，`按小时` 选项置灰。

**日期**：日历下拉，含预设与自定义两区。

预设：`最近 12 小时`、`最近 24 小时`、`最近 3 天`、`最近 7 天`、`最近 30 天`。

自定义：双月日历，点击起始日后点击结束日确定区间；已选区间高亮；支持跨月翻页。

联动规则：选「最近 12 小时」或「最近 24 小时」时粒度自动切到`按小时`。自定义区间跨度为 1 天时同样如此。其余情况保持用户当前选择。

日期控件自带输入不落盘，只在内存中保存当前区间。

面板定位：日历面板挂在筛选行下（不是日期触发器内），相对整行 `right:0` 右对齐。面板宽约 560，若跟着触发器左缘向右展开，一旦触发器靠右就会顶出弹窗右缘；弹窗内容区横向不滚动，超出部分会被直接裁掉，日历右半边的月份和「确定」按钮都会消失。右对齐后左边缘 = 容器右缘 - 560，配合 `max-width:100%` 保证两侧都不越界。

### 4.4 概览卡

一行六格：总用量、输入、输出、实测 / 估算（同时显示两个数，不求和）、缓存命中率、会话数。

字段口径：各数值都是把记录里同名字段直接相加，不做再推导。`cache_read`、`cache_write`、`reasoning` 是独立字段，不计入 `input` 或 `output`。不同供应商对「输入是否已包含缓存读取」的定义不一致，因此缓存命中率统一定义为 `cache_read / (cache_read + input)`，不假设 `input` 与 `cache_read` 的包含关系。

数值用现有的 `formatTokens()` 格式。

### 4.5 折线图

- 每个时间桶两点，输入用 `--cyan`、输出用 `--green`；
- 图例可点击隐藏序列，被隐藏的序列同时退出纵轴量程计算；
- 描点 + 网格 + 纵轴自适应刻度；
- 参与缩放。

### 4.6 饼图

- 分组为「模型用量」：按 `total` 取前 6 个模型，其余合并为「其他」；
- 分组为「模型用量」且模型下拉选中了某一个模型：改为该模型的 token 构成（输入 / 输出 / 缓存读 / 缓存写）。否则只剩一个满圆，图没有信息量；
- 分组为「供应商用量」：按供应商切分；
- 环形，中心显示当前范围总量，扇区 hover 高亮并把该分组数值打到中心，右侧图例带百分比；
- 分组名称用配置里的显示名（模型的 `name`、供应商的 `name`），而不是历史记录里的裸 ID；
- 不参与缩放。

### 4.7 柱状图

- 每个时间桶一根堆叠柱：实测（`--cyan` 实心）+ 估算（`--orange` 斜纹）；
- 与折线图共享同一时间视窗，缩放与平移同步；
- 与折线图同样支持纵轴缩放。

### 4.8 明细表

- 分组为「模型用量」：列为 模型 / 供应商 / 总量 / 输入 / 输出 / 实测 / 估算 / 轮次；分组为「供应商用量」时，首列换成 供应商，去掉供应商列；
- 名称列显示配置里的显示名，并把完整的 `provider/model` 键放在单元格 `title` 里，鼠标悬停即可与设置页逐字对照；
- 点击表头切换升/降序，默认按总量降序；
- 数值列右对齐，用 `formatTokens()` 显示。

### 4.9 缩放交互

作用于折线图与柱状图，两图时间视窗联动：

| 操作 | 行为 |
|---|---|
| 滚轮 | 以鼠标所在时间为锚点缩放时间轴 |
| 拖拽 | 平移时间视窗 |
| 双击 | 重置为筛选器选定的完整区间 |
| Shift + 滚轮 | 缩放纵轴 |

下钻规则：按天桶只落在自然日零点，窄视窗里可能一个桶都落不进来，图会只剩空坐标系。因此可见跨度不足 3 个当前粒度的桶时（按天即不足 3 天），无论粒度下拉当前是哪个档位，都改用小时桶渲染。这就是「缩放突破限制、放大到小时」的实现方式，纯客户端行为，不产生新请求。缩回后回到粒度下拉选定的档位。

服务端返回 `resolution` 为 `"day"`（跨度超过 90 天）时没有小时桶可下钻，缩放只改变视窗而不改变粒度。

纵轴在任意视窗下重新计算刻度，不出现半截数字。视窗不得超出筛选器区间之外，只能在其内部缩放平移。

平移贴到区间边界时钳制的是偏移量而不是两端，视窗跨度保持不变，不会因为拖到边缘就把缩放层级压扁。

### 4.10 状态与请求

```javascript
state.usage = {
  loaded: false, loading: false, error: "",
  range: {preset: "7d", start: null, end: null},
  granularity: "day",          // day | hour
  groupBy: "model",            // model | provider
  provider: "",                // 空为全部供应商
  model: "",                   // 空为全部模型
  catalog: {},                 // provider/model → {name, provider, providerName}，仅用于名称映射
  providerOptions: [],         // 供应商下拉选项，来自 candidates
  modelOptions: [],            // 模型下拉选项，来自 candidates，随 provider 收窄
  token: 0,                    // 请求令牌，用于丢弃过期响应
  data: null,
  view: {start: null, end: null},   // 缩放视窗，null 表示全区间
  sort: {key: "total", desc: true},
}
```

- 首次切到「用量」Tab 时懒加载，与 MCP Tab 的既有做法一致；进入前先确保配置的模型目录已就绪，显示名映射依赖它；
- 仅「日期区间变化」「供应商变化」「模型变化」触发请求，粒度与分组切换纯前端；
- 请求按 `(start, end, provider, model)` 在客户端也做一层结果缓存，来回切换即时响应；缓存条目有上限（32 条），超出即整体重置。key 精确到分钟，跨分钟后旧条目再也不会命中，不设上限会随反复切换一直堆积；
- 每个请求带递增令牌，响应回来时令牌已过期就丢弃，避免快速切换筛选时旧结果写进新视图。**命中缓存时同样要递增令牌**，否则仍在飞的请求返回时令牌还对得上，会把刚渲染的缓存结果覆盖成上一个筛选的数据；
- 请求中显示加载态并禁用刷新按钮；
- 失败时显示错误文案，保留上一次数据不清空。

## 5. 图表模块契约

`charts.js` 暴露三个渲染函数与一个缩放控制器，不依赖 `app.js`：

```javascript
Charts.line(container, {buckets, series, view, onViewChange})
Charts.pie(container, {groups, unit})
Charts.bar(container, {buckets, view, onViewChange, onHover})
```

- `container` 为 DOM 元素，函数内部清空后重建 SVG；
- `onViewChange` 回传新的时间视窗，由 `app.js` 分发到折线图与柱状图，实现联动；
- 缩放控制器内部维护「按鼠标定位的缩放锚点」与拖拽平移，不读取 `app.js` 的状态；
- 全部输出为 SVG 元素与属性，不引入任何外部依赖，满足内网离线打包要求。

## 6. 主题与可访问性

- 配色只使用既有 CSS 变量（`--cyan`、`--green`、`--orange`、`--line`、`--muted`、`--surface-*`），深色 / 银白 / 蔚蓝三套主题自动适配；
- 图表容器带 `role="img"` 与 `aria-label`，概览卡与明细表提供文本等价信息；
- 下拉控件使用 `button` + `role="listbox"` / `role="option"` 语义，支持键盘上下移动与 Enter 选择；
- 日历使用 `role="dialog"`，支持 Escape 关闭并把焦点还给触发按钮；
- 加载与错误通过 `aria-live` 通知。

## 7. 空状态与边界

- 所选范围内无记录：显示「所选范围内没有用量记录」，不画空坐标系；
- `resolution` 为 `"day"`：`按小时` 粒度置灰；
- 记录缺少 `usage.model`：计入「未知供应商」，明细表中单列一行；
- 历史出现过但已不在配置中的模型：仍在候选列表里，名称后标注「未在配置中」；
- 时间窗内没有任何记录：候选列表为空，两个下拉只有「全部」两项，图表与表格走空状态；
- 已选中的模型或供应商在当前时间窗内没有记录：保留下拉里的选中项，不静默清空；
- 未配置任何模型：候选列表仍按历史记录生成，显示名退回原始键；
- 选定的供应商与模型组合自相矛盾（模型不属于该供应商）：不会发生，选模型时会自动对齐供应商；若通过其他途径构造出该组合，返回零值结构而不报错；
- 视窗缩放至只剩一个桶：仍渲染该桶，不做特殊处理。

## 8. 测试标准

### 8.1 后端

- 按小时切桶正确，跨自然日边界不错位；
- 实测与估算分开累计，`measured + estimated == total`；
- 供应商归属从前缀解析，缺 `model` 时回落会话 `model_id`，再缺则记 `unknown`；
- `model` 参数只统计指定模型；
- `provider` 参数只统计指定供应商，且同时作用于 totals、buckets、providers、models 四处；
- `provider` 与 `model` 同时给出时取交集，矛盾组合返回零值结构；
- 不同筛选条件各自命中独立缓存条目，来回切换互不污染；
- `candidates` 只按时间窗过滤，给出筛选条件后仍返回完整候选，不随筛选缩水；
- `candidates` 不含时间窗外的模型；
- `candidates` 的显示名取自 `provider_names`；
- 跨度超过 90 天时 `resolution` 为 `"day"`；
- 会话文件未变化时命中缓存，`_read_jsonl` 不被重复调用；
- 新消息写入后缓存失效并反映到统计结果；
- 无记录的时间窗返回零值结构；
- 没有 `usage` 字段的旧记录被跳过且不报错。

### 8.2 前端契约

- 设置中心含四个 Tab，用量为第四个；
- 五个筛选控件存在，顺序为 分组 / 供应商 / 模型 / 粒度 / 日期，默认值为 模型用量 / 全部供应商 / 全部模型 / 按天 / 最近 7 天；
- 供应商与模型下拉只列当前时间窗内有调用记录的项，而不是配置里的全部模型；
- 下拉里的显示名与设置页一致，历史遗留模型标注「未在配置中」；
- 三个图表容器与明细表都已渲染；
- 切到用量 Tab 才发起首次请求；
- 切换粒度、分组不发新请求；
- 日期区间、供应商或模型变化才发起请求。

### 8.3 交互

- 滚轮缩放锚定鼠标位置；
- 拖拽平移不越出筛选区间；
- 双击重置视窗；
- Shift + 滚轮缩放纵轴；
- 可见桶数不足时下钻到小时桶；
- 折线与柱状视窗联动；
- 切换分组后饼图与明细表同步换维度；
- 切换分组不清空已选的供应商与模型，也不置灰模型下拉；
- 选择模型后供应商自动对齐到该模型所属供应商；
- 切换供应商后，不属于新供应商的已选模型回落到「全部模型」；
- 选择某个模型或供应商后，表格与图表立即刷新，不需要手动点刷新按钮；
- 切换日期区间后下拉选项随之更新，已选中的项若在新区间内无记录仍保留在列表中；
- 发请求后立刻切到另一个有缓存的区间，晚到的响应不会覆盖当前视图；
- 结果缓存条目数不会无限增长；
- 供应商与模型下拉里显示的显示名与设置页一致；
- 明细表名称列悬停可见完整 `provider/model` 键；
- 选择「最近 12 小时」后粒度自动切到按小时；
- 自定义日历区间跨月选择正确；
- 明细表表头排序切换正确；
- 分组为「模型用量」且选中单个模型时，饼图切换为该模型的 token 构成，不是满圆；
- 缓存命中率按 `cache_read / (cache_read + input)` 计算；
- 空范围显示空状态。

## 9. 首版不包含

- Qt 客户端的用量面板；
- 用量数据的导出；
- 按费用（货币）折算，仅统计 token；
- 供应商侧账单对账；
- 用量告警与阈值通知；
- 跨设备或多用户汇总。
