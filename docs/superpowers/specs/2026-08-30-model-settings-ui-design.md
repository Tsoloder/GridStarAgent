# 模型设置中心 UI 设计

## 1. 目标与范围

在聊天页模型选择行最右侧增加设置按钮。点击后打开设置中心，包含三个 Tab：

- 模型
- 技能
- MCP 工具

首版完整实现“模型”设置；“技能”和“MCP 工具”仅显示空状态及“即将支持”。

模型设置支持：

- 供应商新增、编辑与删除；
- API 地址、API Key、环境变量名和默认协议配置；
- 使用未保存配置测试连接；
- 独立读取供应商模型列表；
- 从可搜索下拉框或手动输入添加模型 ID；
- 模型级协议与能力覆盖；
- 顶部模型选择按供应商进行不可折叠的树形分组展示。

本设计是已批准的 Python 多 Provider 架构的 WebUI 配套设计，不改变 MCP 工具定义和参数。

## 2. 页面布局

### 2.1 模型选择行

模型选择控件保留原位置，设置按钮放在该行最右侧。设置按钮具有可访问名称“打开设置”，点击后打开居中设置弹窗。

原生 `select` 替换为自定义 Listbox，因为原生控件无法稳定呈现不可折叠的分组树和模型次要信息。

模型菜单示例：

```text
OPENAI
  ✓ GPT-5 Mini      gpt-5-mini
    GPT-5           gpt-5

ANTHROPIC
    Claude Sonnet 4 claude-sonnet-4
```

规则：

- 供应商分组始终展开，不提供折叠按钮或折叠状态；
- 供应商标题不可选；
- 禁用的供应商和模型不显示；
- 当前模型显示勾选状态；
- 会话保存完整的 `provider/model` 标识；
- 菜单过长时内部滚动；
- 支持点击外部和 Escape 关闭；
- 支持上下方向键移动、Enter 选择；
- 输入字符可按显示名称或模型 ID 搜索定位。

### 2.2 设置弹窗

弹窗由标题栏、Tab、内容区和底部操作栏组成。

顶部 Tab：

```text
模型 | 技能 | MCP 工具
```

首版只有模型 Tab 可用。技能与 MCP 工具 Tab 可切换，但只展示空状态，不保存任何配置。

模型 Tab 采用方案 A：

- 左侧：供应商导航、模型数量和新增供应商按钮；
- 右侧：当前供应商设置、连接状态、已添加模型和添加模型区域；
- 底部：取消和保存设置。

关闭时若草稿有修改，提示是否放弃；没有修改则直接关闭。

## 3. 前端状态

新增独立状态：

```javascript
state.settings = {
  open: false,
  activeTab: "models",
  activeProviderId: null,
  original: null,
  draft: null,
  revision: null,
  dirty: false,
  testingProviderId: null,
  readingProviderId: null,
  discoveredModels: {},
  validationErrors: {}
}
```

- `original`：打开弹窗时从服务端取得的配置；
- `draft`：表单只修改草稿；
- `revision`：用于保存冲突检测；
- `dirty`：控制关闭确认；
- `discoveredModels`：按供应商保存当前弹窗生命周期内读取的候选模型；
- `validationErrors`：按字段路径显示错误；
- 测试和读取状态按供应商隔离。

弹窗关闭后清理草稿和候选列表；重新打开时读取服务端最新配置。

## 4. 供应商设置

### 4.1 新增供应商

点击“添加供应商”后选择预设类型：

| 类型 | 默认 API 地址 | 默认协议 | 模型发现 |
|---|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `openai-responses` | OpenAI `/models` |
| Anthropic | `https://api.anthropic.com` | `anthropic-messages` | Anthropic 模型接口 |
| OpenAI-compatible | 空 | `openai-chat` | OpenAI `/models` |
| Ollama | `http://localhost:11434/v1` | `openai-chat` | OpenAI `/models` |

前端生成不冲突的供应商 ID，加入左侧导航并立即选中。名称、API 地址、Key、环境变量名和默认协议均可编辑。

### 4.2 可编辑字段

- 供应商名称；
- 供应商类型；
- API 地址；
- API Key；
- API Key 环境变量名；
- 默认 API 协议；
- 启用状态。

供应商已经包含模型后，不允许直接修改类型；用户需新建供应商后迁移模型。

### 4.3 API Key

- 密码输入框只显示脱敏占位，不回传原 Key；
- 用户输入新值时才标记 Key 已修改；
- 提供明确的“清除 Key”操作；
- 环境变量存在时显示“由环境变量提供”，并禁用明文输入；
- 环境变量优先于明文 Key；
- 日志、错误和配置响应不得包含 Key。

### 4.4 删除供应商

如果供应商仍包含模型或默认模型属于该供应商，则禁止删除并说明原因。用户必须先删除或迁移模型，并修改默认模型。删除不进行隐式级联。

## 5. 测试连接与读取模型

### 5.1 测试连接

测试连接只验证当前表单中尚未保存的 API 地址和 Key，不读取模型、不导入模型、不发送推理请求、不消耗推理 Token。

接口：

```http
POST /config/providers/test
```

请求包含供应商类型、API 地址、认证字段和 headers。后端使用对应供应商的轻量只读端点测试认证和连通性，不自动重试。

成功响应：

```json
{
  "ok": true,
  "latency_ms": 186,
  "status_code": 200,
  "message": "连接成功"
}
```

失败响应使用 authentication、timeout、connection 或 provider_error 等结构化类别。结果在按钮附近内联显示。

### 5.2 读取模型

读取模型是独立按钮，使用当前未保存供应商配置调用模型列表接口：

```http
POST /config/providers/models
```

返回候选模型 ID 和可选显示名称。规则：

- 排序、去重；
- 不自动添加；
- 不覆盖已添加模型；
- 再次读取替换当前供应商的临时候选；
- 不持久化候选列表；
- 读取失败保留上一次候选及已添加模型；
- 不支持模型列表接口时仍可手动输入 ID。

测试连接和读取模型使用独立请求、独立状态和独立错误信息。

## 6. 模型管理

### 6.1 已添加模型

当前供应商下展示已添加模型的名称、ID、协议、能力摘要和删除操作。删除只修改草稿，保存成功后才更新运行时目录。

### 6.2 添加模型下拉框

交互参考用户提供的界面：

- “添加模型”是可搜索下拉框；
- 候选来自“读取模型”；
- 已添加模型显示勾选并禁止重复添加；
- 每项显示模型 ID，可显示上下文窗口等已知元数据；
- 下拉框底部提供手动模型 ID 输入框和确认按钮；
- 候选列表为空时仍可手动添加。

同一供应商内模型 ID 不可重复。首尾空格会去除，大小写保持原样且不做大小写合并。不同供应商可使用相同模型 ID。

### 6.3 新模型默认值

读取或手动添加的模型默认继承供应商协议，即 `api` 保存为 `null`。自动发现无法可靠获得的能力采用保守默认值：

```json
{
  "tools": false,
  "parallel_tools": false,
  "reasoning": false,
  "vision": false,
  "stream_usage": false
}
```

默认 `context_window=32768`，`max_output_tokens=4096`。

### 6.4 高级设置

每个模型可展开高级设置：

- 显示名称；
- API 协议：继承供应商、OpenAI Chat、OpenAI Responses、Anthropic Messages；
- context window；
- max output tokens；
- tools；
- parallel tools；
- reasoning；
- vision；
- stream usage。

协议字段选择“继承供应商”时保存为 `null`。前端只展示与供应商类型兼容的协议，后端仍执行最终校验。

## 7. 配置 API 与保存事务

### 7.1 获取配置

```http
GET /config
```

返回 `revision` 和脱敏配置，包括 default model、providers 和 models。

### 7.2 保存配置

```http
POST /config
```

请求携带打开弹窗时的 `revision` 与完整草稿。后端按以下顺序执行：

1. 严格校验字段；
2. 检查供应商和完整模型标识唯一；
3. 检查协议兼容性及默认模型；
4. 处理脱敏 Key 保留和清除语义；
5. 使用新配置构建 ModelCatalog 和 ModelRuntime 候选实例；
6. 写入临时配置并原子替换正式文件；
7. 原子切换运行时；
8. 返回新 revision、脱敏配置和模型目录。

任一步失败都保留当前运行配置和前端草稿。

如果 revision 已过期，返回 409。前端提示配置已被其他窗口修改，允许重新加载，不覆盖新配置。

### 7.3 保存后的模型选择

- 当前模型仍存在且启用：保持选择；
- 当前模型被删除或禁用：切换到配置中的默认模型；
- 保存成功后刷新顶部供应商分组模型列表；
- 默认模型不存在、禁用或所属供应商禁用时拒绝保存。

## 8. 校验与错误处理

表单内联校验：

- API 地址必须是 HTTP/HTTPS；
- Provider ID 和完整模型键不得冲突；
- 模型 ID 不得为空；
- 协议必须与供应商兼容；
- token 数值为正；
- context window 不小于 max output tokens；
- 默认模型存在且启用。

网络规则：

- 测试连接失败不阻止保存；
- 读取模型失败不删除任何模型；
- 保存失败保留草稿；
- 请求中禁用对应按钮，防止重复提交；
- 切换供应商不让结果写入错误供应商；
- 关闭弹窗时取消仍在执行的测试与读取请求；
- Provider 原始敏感响应不直接展示。

## 9. 可访问性

- 设置按钮、关闭按钮和图标按钮都有文字型 aria-label；
- 弹窗打开后焦点移入，关闭后返回设置按钮；
- Tab 使用标准 tablist/tabpanel 语义；
- 自定义模型选择使用 combobox/listbox/group/option 语义；
- 添加模型下拉框支持键盘搜索、选择和关闭；
- 错误通过 `aria-live` 通知；
- 焦点不离开打开的模态框。

## 10. 测试标准

### 10.1 后端

- 测试连接使用未保存配置且不调用推理；
- 读取模型与连接测试接口独立；
- OpenAI、Anthropic、OpenAI-compatible 和 Ollama 认证正确；
- 模型结果排序、去重和错误分类正确；
- Key 在响应、日志、异常和测试快照中脱敏；
- 配置原子保存；
- revision 冲突返回 409；
- 脱敏占位不覆盖 Key；
- Key 可明确清除；
- 无效默认模型和协议配置拒绝保存。

### 10.2 前端契约

- 设置按钮位于模型行最右侧；
- 设置弹窗包含三个 Tab；
- 首版只有模型设置可用；
- 左侧供应商导航存在；
- 测试连接和读取模型按钮独立；
- 添加模型支持搜索候选和手动 ID；
- 高级设置支持协议覆盖；
- 顶部模型选择按供应商分组且无折叠控件；
- 现有工具调用分组折叠不受影响。

### 10.3 交互

- 新增、编辑和受约束删除供应商；
- 测试连接；
- 读取并添加模型；
- 手动添加模型；
- 防止重复模型；
- 未保存关闭确认；
- 保存失败保留草稿；
- revision 冲突处理；
- 删除当前模型后回退默认模型；
- 两个自定义下拉框的键盘操作；
- 网络请求竞态不串写供应商。

## 11. 首版不包含

- 技能设置具体功能；
- MCP 工具设置具体功能；
- 拖拽排序供应商或模型；
- 根据模型名称自动猜测能力；
- 测试连接时发送最小聊天请求；
- 自动把读取结果全部导入；
- 删除供应商时级联删除模型。
